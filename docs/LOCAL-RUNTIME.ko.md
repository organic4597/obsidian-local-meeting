# 로컬 음성 엔진 자동 연결

적용 버전: 0.14.0-beta.4 · 2026-11-11

## 사용자 흐름

플러그인을 켜면 설치된 음성 인식·화자 분석·대사 정렬 실행환경을 자동으로 찾는다. 일반 설정에는 **음성 처리 엔진**의 연결 상태와 **자동으로 다시 연결** 버튼만 표시한다. Python 실행 파일과 모델의 절대 경로는 별도 **고급 문제 해결 → 열기** 창으로 옮겼다. 연결 문제가 없으면 이 창을 사용할 필요가 없다.

회의록 기본 폴더, 오디오 저장 위치, 인원 등 사용자가 선택할 설정은 유지한다. 원본 녹음과 기존 회의록·필기·화자 교정은 자동 이동하거나 재처리하지 않는다. 새 설치에서 오디오 기본 위치가 비어 있으면 이 Mac의 사용자 앱 데이터 폴더 아래 `obsidian-local-meeting/recordings`를 사용한다. 기존 지정 위치와 사전·프로필 공통 저장소는 유지한다.

파일이 아직 없으면 설치가 필요한 항목을 표시한다. **자동 연결은 이미 설치된 파일을 찾는 기능**이다. 모델 가중치, Python과 의존 패키지를 인터넷에서 내려받아 설치하는 초기 설치 도구는 이번 변경에 포함하지 않았다. Community-1의 모델 이용 조건 동의와 다운로드 인증도 기존처럼 필요하다. 설치가 완료됐다고 잘못 표시하거나 회의 도중 대용량 다운로드를 시작하지 않는다.

## 탐색과 저장

다음 순서로 사용할 수 있는 경로를 선택한다.

1. 해당 Vault에 저장한 유효한 기존 값.
2. 플러그인 폴더의 `local-runtime.json` 설치 정보. 이전 세 필드 형식도 지원.
3. `~/Library/Application Support/obsidian-local-meeting/runtime/local-runtime.json`의 이 Mac 공용 연결 정보.
4. 공용 runtime 폴더, 플러그인 폴더 및 기존 실행환경의 설치 기준 폴더에서 `.venv`, `.venv-community`, `models`의 정해진 구조.
5. Community-1 공식 모델의 표준 Hugging Face 로컬 캐시.

디스크 전체를 재귀 탐색하거나 네트워크를 조회하지 않는다. 유효한 수동 경로가 있으면 자동 후보로 덮어쓰지 않는다. 경로가 사라진 경우 다른 유효 후보를 사용한다. 모든 구성요소가 확인되면 최소 연결 정보만 권한 600의 로컬 파일로 원자적으로 저장한다. 새로운 Vault에서도 같은 설치를 재사용할 수 있다. 인증 토큰·회의 내용은 이 파일에 넣지 않는다.

실행 파일에는 절대 경로·파일 존재·실행 권한을 검사한다. ASR·정렬 모델은 설정·토크나이저·가중치를 확인하고 분할 가중치는 모든 참조 파일이 있어야 한다. Community 모델은 처리에 필요한 다섯 파일을 확인한다. 파일 검사는 패키지 호환성이나 모델 추론의 성공을 보증하지 않는다. 경로 자동 검색은 모델을 메모리에 적재하지 않는다.

## 검증

자동 검사 238개(TypeScript 162, Python 76)를 통과했다. 새 Vault에서 공용 설치 탐색, 유효한 수동 설정 보존, 사라진 경로 대체, 이전 설치 정보에서 ASR 경로 유추, 미완료 모델·실행 권한 거부, 분할 가중치 누락·상위 경로 참조 거부를 검사했다.

현재 Mac에서도 기존 설치와 경로 설정이 비어 있는 가상의 새 Vault 양쪽에서 다섯 구성요소를 자동 탐색했다. 별도 프로세스로 ASR 의존 패키지와 Metal 지원, Community 의존 패키지와 MPS 지원을 확인했다. 원음 녹음·재생·실제 회의 외부 전송은 실행하지 않았다. 새 컴퓨터의 무인 설치나 자동 다운로드를 검증했다는 의미는 아니다.

Obsidian 1.15.0 실제 설정 화면에서 엔진 자동 연결 상태와 자동 재연결 성공을 확인했다. 일반 화면에 Python·모델 경로가 없고 고급 문제 해결 창에서만 표시되는 것을 확인한 뒤 닫았다. 사용자 경로와 기존 회의 파일을 원래 값으로 복구·확인했다.
