# M4 로컬 STT 초기 실측

2026-10-25 · Apple M4 / 통합 메모리 24GB · Python 3.11 · mlx-qwen3-asr 0.4.4 / MLX 0.32.4.

모델: TeamUNIVA/qwen3_asr_1.7b_ko. 원본 SHA-256: `eceffd53d29eba47f68da83c3c5efb312c356ceea1721b8b5129e6e1f43e49dc`. 동일 원본을 group size 64로 변환했다. 8비트는 인코더와 디코더 모두 8비트이며, 혼합 4비트는 인코더 8비트·디코더 4비트다.

입력은 macOS Yuna로 생성한 한국어 합성 음성 8.305초, 16kHz mono PCM16 WAV다. 모델별 독립 프로세스에서 3회 전사했으며 표에는 첫 실행을 제외한 2회 범위를 표시한다. 두 측정 시점의 시스템 부하는 완전히 통제하지 않았다.

8비트 첫 전사는 2.657초, 혼합 4비트 첫 전사는 0.897초였다. 첫 실행 성능은 캐시·컴파일 상태의 영향을 받으므로 일반적인 초기 지연 보증이 아니다. RSS는 모델 로딩을 포함한 전체 프로세스 high-water 값이며, Metal은 다른 범위의 별도 메모리 카운터다. 두 수치를 더하지 않는다. 이 수치는 ASR 단독이며 Obsidian·화자 구분·요약 모델을 포함하지 않는다.

두 변환본 모두 이 짧은 샘플에서 동일한 텍스트를 생성했다:

> 오늘 회의를 시작하겠습니다. 민수 씨는 다음 주 금요일까지 보고서를 작성해 주세요. 다음 회의는 월요일 오후 3시입니다.

이는 실제 M4에서 한국어 미세조정 모델 변환과 추론이 작동한다는 기능 확인이다. FLEURS 한국어 평가, 실제 다중 화자 회의 정확도, 장시간 안정성 및 4비트 품질 동등성을 입증하지 않는다.

8초 고정 파일 구간의 마지막 0.305초를 별도로 전사하면 앞 구간에서 이미 완성한 ‘입니다.’가 중복됐다. 파일 가져오기에서 짧은 마지막 구간을 직전 오디오에 합치도록 보완했다. 실시간 마이크 경계의 중복·누락을 일반적으로 해결한 것은 아니며 말끝 감지·스트리밍 확정 로직이 후속 과제다.

## STT + 화자 모델 동시 로딩 실측

현재 M4에서 한국어 Qwen 8비트(Metal)와 Nemotron 3 Q8_0(CPU)을 한 워커에 로딩하고, 19.386초짜리 A→B→A 합성 음성을 처리했다. 프로세스 피크 RSS는 **2.890GB**였다. 이는 짧은 샘플의 로딩·추론 피크이며 Obsidian 자체와 캘린더 보조 프로세스를 제외한다. 장시간 회의 피크나 상시 예약 메모리 보증이 아니다.

화자 모델 파일 SHA-256: `08456d9e22cd9a323c0364d98375f3746d6e68507ebb705cd46438c534c7a3a1`. NVIDIA 공식 NeMo-Speech.cpp 0.2.0 C ABI를 사용한다. 샘플에서 익명 ID 1→2→1과 세 개의 발언 구간을 확인했다. 한국어 실회의 DER은 아직 측정하지 않았다.
