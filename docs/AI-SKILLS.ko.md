# AI 정리 스킬 — 0.14.0-beta.1

설정 → Local Meeting → **AI 정리 스킬**에서 네 스킬을 각각 켜거나 끌 수 있다. **OpenAI 연결 및 정리** 창에도 같은 토글을 제공한다. 네 스킬은 처음에 모두 켜져 있으며, 저장된 명시적 꺼짐 설정은 업데이트와 재시작 후에도 유지한다.

- **summarize-meeting · 회의 요약**: 주제·명시된 결정·할 일·담당자·기한·미결 사항을 정리한다.
- **stop-slop-ko · 한국어 문장 정리**: 정보와 회의록 항목 형식을 유지하며 반복·과장·군더더기를 줄인다.
- **im-not-ai · 사실 보존 윤문**: 필요한 문장만 보수적으로 다듬고 고유명사·숫자·날짜·인용·핵심 의미의 보존을 우선한다.
- **K-Humanizer · 업무 한국어**: 전문 용어와 업무 문체, 요청·제안·약속과 조건·확실성의 차이를 보존한다.

원본 지침은 [출처와 적용 범위](../skills/README.ko.md)에 기록했다. 네 프로젝트는 각자의 MIT 고지와 커밋을 포함해 배포한다.

## 동작

회의 종료 후 기존 화자 분석과 본문 반영이 끝나면, 선택한 고정 지침을 기존 요약·할 일·일정·용어 추출 요청에 결합한다. 모델 요청은 한 번이며 스킬별로 별도 API를 호출하지 않는다. 모델 목록 조회나 로그인 요청은 기존 연결 과정으로 별개다. 모두 끄면 기존 기본 정리 규칙과 구조화된 출력 검증만 사용한다.

스킬을 켜는 것만으로 API 요청·재전사·기존 회의 재정리를 시작하지 않는다. 설정 변경은 다음 수동 정리 또는 다음 회의의 자동 정리부터 적용한다. 정리 중에는 토글 저장을 막으며, 저장 실패 시 이전 값으로 되돌린다.

각 요청에는 켠 스킬과 지침 해시의 스냅샷을 저장한다. 스킬 조합·원본 커밋·적용 지침 버전이 바뀌면 입력 버전도 달라져 이전 결과를 잘못 재사용하지 않는다. 같은 입력과 설정의 완료 결과는 기존 재시도 경로에서 재사용한다. 스킬 설정 변경 후에는 기존 정리가 이전 설정 기준임을 표시한다.

새 조합으로 정리하면 별도 정리 노트를 만들고 이전 정리 노트·체크박스·수동 수정은 그대로 남긴다. 전사 원문·필기·화자 이름과 수동 배정은 유지한다. 검토 항목도 이전 결과와 구분해 저장하며 일정·할 일·사전을 자동으로 다시 등록하지 않는다.

## 적용 범위와 한계

이 기능은 원본 스킬의 지침을 회의록 API용으로 재구성한 고정 어댑터다. 원본 스킬을 실행하는 에이전트나 셸을 추가한 것이 아니다. im-not-ai 원본의 진단 스크립트·변경률 검사·다단계 에이전트 워크플로는 포함하지 않으며 수치 검사 통과를 주장하지 않는다.

사실·수치·직접 인용·근거·화자·시각·담당자·날짜·기한과 조건·확실성의 보존 규칙이 문체 지침보다 우선한다. 상대 날짜는 기존 회의 시작일 기준 변환을 유지한다. 구조·근거 ID·날짜·인물별 발언 귀속 검증은 계속 수행하지만, 지침만으로 모든 문장의 사실 보존이나 문체 품질을 자동 보증하지는 않는다.

## 검증

자동 검사 228개(TypeScript 152, Python 76) 통과. 16가지 조합의 요청 포함 여부와 한 번의 모델 호출, 조합별 캐시 구분, 잘못된 스킬 버전 차단, 설정 저장 실패 복구, 기존 노트·전사·필기·수동 화자 유지와 원본 라이선스·해시를 검사했다. 실제 회의록을 외부로 보내는 품질 비교는 수행하지 않았다.
