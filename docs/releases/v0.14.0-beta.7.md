# 0.14.0-beta.7 · AI 용어의 사전 추가 복구

현재 회의에서 SLM·OCR이 선택한 프로젝트 사전에 이미 존재하지만 추가 버튼이 중복 오류를 반환하는 것을 확인했습니다. 같은 범위·표기의 기존 항목은 실제 사전 ID로 연결하고 중복 저장하지 않습니다. 기존 별칭·교정 정책·활성 상태·수정 버전은 보존합니다. 새 등록 ID는 범위와 표기를 포함해 안정적으로 만들며, 사전 쓰기 후 검토 기록 저장이 실패해도 재시도 시 중복을 만들지 않습니다.

등록 결과는 해당 행에 즉시 표시하고 입력과 추가 버튼을 잠급니다. 다른 행을 편집 중일 때에도 그 편집을 잃지 않고 완료 상태를 표시합니다. 실패 시 이유를 행 안에 남기고 재시도할 수 있게 하며, 연속 클릭으로 중복 요청이 실행되지 않도록 합니다. 사전 저장에 성공했지만 적용 상태 갱신만 실패한 경우에는 저장 완료와 갱신 문제를 구분해 알립니다.

기존 검사와 회귀 검사 총 248개(TypeScript 169, Python 79)를 통과했습니다. 실제 Python 사전 DB를 사용해 기존 항목·별칭·비활성 상태 보존, 기록 단계 실패 후 재시도, 범위별 등록 분리와 갱신 실패를 확인했습니다. 버튼 검사에서는 다른 편집 보존, 즉시 완료 표시, 이중 클릭 차단, 오류 표시와 재시도를 검증했습니다.

사전 등록은 확인한 표기를 보관하는 동작이며, beta.6에서 중지한 ASR 용어 목록 프롬프트 주입을 다시 켜지 않습니다. 새 항목에 발음 별칭을 자동 생성하거나 기존 회의 문장을 바꾸지 않습니다.

Obsidian 1.15.1 실제 회의의 SLM·OCR 추가 버튼을 눌러 기존 항목 연결과 저장 완료 표시·버튼 비활성화를 확인했습니다. 사전 DB의 모든 항목 값이 시험 전과 같아 중복 추가나 기존 설정 변경이 없음을 확인했습니다. 두 검토 항목에 실제 사전 ID의 완료 기록만 남겼고 원문·정리 노트·전사·WAV 해시는 그대로였습니다. 오디오 재생이나 AI 추론 요청은 수행하지 않았습니다.
