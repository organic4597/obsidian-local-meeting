# 사전 목록 복창과 전사 패널 수정

0.14.0-beta.6 · 2026-11-13

## 확인한 문제

최근 회의의 저장된 전사 98개 중 사용자 보고와 같은 긴 용어 목록을 포함한 구간 18개를 확인했다. 목록 순서가 회의 사전의 recognitionHint 순서와 일치했다. 당시 ASR의 context에 이 목록을 그대로 전달했다. 무음 판정도 신경망 VAD가 아닌 -50dBFS 에너지 기준이어서 배경 소음이 있는 침묵은 모델에 들어갈 수 있었다.

원본 07:03.760–07:04.080과 07:05.720–07:09.720을 읽기만 하여 기존 사전 context와 빈 context로 각각 추론했다. 기존 context에서는 두 구간 모두 목록 복창이 재현됐고 빈 context에서는 복창이 없었다. 두 번째 구간의 스트리밍 4회 중간 출력 및 최종 출력에서도 빈 context로는 목록 복창이 없었다. 소리는 재생하지 않았고 API도 호출하지 않았다. 이는 두 문제 구간의 회귀 검사이며 모든 환경의 오인식 제거를 보증하는 정확도 평가는 아니다.

## 수정

- 실시간 스트리밍·완료 전사·종료 후 재전사 모두 사전 목록을 decoder context로 주입하지 않는다. 사용자 확인된 별칭의 전사 후 표기 교정과 사전 저장은 유지한다. 사전 UI에도 주입 중지를 표시한다.
- 매우 조용한 새 구간은 추론을 건너뛴다. 모델 출력에도 같은 에너지 검사를 적용한다. 기준은 20ms 프레임 중 최소 6개가 -50dBFS 이상인 경우다. 신경망 VAD가 아니며 배경 소음과 발화를 완벽하게 구분하지 못한다. 아주 짧거나 약한 발언이 보류될 수 있고 원음은 항상 보존한다.
- 출력 전체가 인식 힌트 용어로만 이루어졌고 서로 다른 용어가 6개 이상이면서 힌트 목록의 80% 이상인 경우 본문 출력을 보류한다. 일부 약어를 말한 일반 문장이나 짧은 용어 나열까지 제거하지 않는다. 보류 원인은 asrSuppression, 원래 출력은 suppressedRawText에 남긴다. 실제로 긴 사전 목록을 그대로 읽은 경우도 보류될 수 있다.
- 원본 WAV·큐는 잘라내지 않는다. 기존에 편집한 회의록·AI 정리·화자 수정은 자동 정리하거나 삭제하지 않는다. 이미 들어간 잘못된 문장은 이번 업데이트로 자동 복구되지 않는다.

## 전사 표시

문서 끝의 block widget 대신 편집기 아래쪽 CodeMirror panel을 사용한다. 필기 영역을 스크롤해도 패널은 같은 위치에 있고, 전사 영역은 기본 높이 180px의 내부 스크롤을 쓴다. 작은 창에서는 최대 26vh로 줄인다. 새 전사가 들어올 때는 최신 내용을 따라가되 사용자가 이전 발언으로 올려 읽으면 그 위치를 유지한다. **최신 발언 따라가기**로 다시 맨 아래에 붙인다. 전사 패널 자체는 문서 내용을 수정하거나 커서를 옮기지 않으며 본문 확정은 기존 사용자 수정 보호 경로를 유지한다.

## 검증과 배포

자동 검사 244개(TypeScript 165, Python 79) 통과. 기존 필기·화자 수동 수정 보호와 전사 패널 state 유지, 사전 목록 복창 판별과 정상 약어·문장 보존, 무음/저레벨 소음 차단을 포함한다.

동일 패널 코드를 사용하는 격리된 CodeMirror 화면에서 긴 필기와 150줄 전사를 사용해 고정 위치, 높이·내부 스크롤, 이전 발언 읽기 위치 유지, 최신 따라가기, 동시 필기의 DOM 검사 5개를 통과했다. 이 검사는 별도 화면이며 Obsidian에서 장시간 실제 녹음을 수행한 시험은 아니다. Obsidian 1.15.1에서는 업데이트 재로드와 플러그인 활성화를 확인했다.
