# 스트리밍 전사와 필기 시간 연결 — 0.13.0-beta.4

새 회의는 Qwen MLX Session의 문맥 유지 스트리밍 API를 사용한다. 녹음 PCM은 1초 단위 디스크 큐에 저장하면서 하나의 연속 WAV도 유지한다. 전사에는 아직 공급하지 않은 샘플만 순서대로 넣고, 진행 중 발언은 같은 ID의 provisional 개정으로 고스트 영역에 표시한다. 약 0.9초의 쉼 또는 최대 20초에서 발언을 확정하고 다음 발언의 스트리밍 상태를 시작한다. 임시 결과는 문맥에 따라 바뀔 수 있다. 긴 발화는 20초씩 확정하므로 전체 회의 음성·텍스트를 모델 상태에 무제한 쌓지 않는다.

Community-1의 최근 창 분석은 별도 프로세스이며 STT는 그 결과를 기다리지 않는다. 분석 범위가 갱신되면 최근 120초의 발언에 같은 ID로 화자 개정을 보낸다. 화자의 최근 5초를 보류하는 정책은 화자 배정에만 적용한다. 전사 내부는 화자 경계를 기다려 자르지 않으며 여러 사람의 발언이 하나의 임시 문장에 포함되면 미확정/동시 발언일 수 있다. 종료 후 단어 시간 정렬과 전체 화자 분석으로 나눈다. 즉각적인 끼어들기 단어별 분리를 보장하지 않는다.

고스트 갱신은 문서 변경이 아니므로 필기·커서·Undo 이력과 분리된다. 이미 표시한 내용의 개정과 뒤늦은 화자 이름은 제자리에서 바뀌며 전체를 다시 타이핑하지 않는다. 수동으로 수정한 발언과 화자는 기존 잠금 정책을 우선한다. 아직 진행 중인 발언의 텍스트 전체를 직접 잠그면 해당 발언의 후속 자동 텍스트는 덮어쓰지 않으므로, 텍스트 교정은 발언 확정 후 진행하는 편이 좋다.

## 필기 시점

녹음 프로세스는 STT 처리와 독립적으로 샘플 수·샘플레이트·관측 시각을 전달한다. 편집기의 사용자 입력·수정 범위를 이 오디오 시계에 연결해 meeting.json의 noteTimings에 저장한다. 원문에 시간 문법을 삽입하지 않는다. 짧게 연속된 인접 입력은 한 묶음으로 기록한다. 입력 시점과 관측 시계의 차이를 바탕으로 오차 추정을 함께 보관한다. 신선한 녹음 시계가 없으면 임의 시간을 붙이지 않는다. 이 오차는 장치·OS 전체 지연을 보장하는 측정값은 아니다.

노트가 수정되면 범위를 이동하고 삭제한 필기는 삭제 상태로 남긴다. 여러 편집기의 동일 변경은 중복 적용하지 않는다. 오프라인 또는 외부 편집은 범위만 재연결하며 새 녹음 시각을 추측하지 않는다. 기존 회의 필기에 소급해 시간을 붙이지 않는다.

상세 보기의 **필기 시점 검토** 또는 명령어 **로컬 회의록: 필기 시점과 주변 발언 검토**에서 필기와 전후 10초의 발언을 함께 확인하고 주변 녹음을 들을 수 있다. 녹음 재생 버튼은 실제 소리를 내므로 시험에서는 누르지 않았다.

기존 OpenAI 정리 요청에는 최신 필기, 입력 시각, 주변 발언 ID를 함께 제공한다. 시간상 근접함을 사실의 증명으로 사용하지 않으며 필기와 발언이 충돌하면 확인사항으로 남기도록 요청한다. 별도 자동 API 호출·원문 덮어쓰기는 추가하지 않는다.

## 복구와 호환성

확정한 오디오 위치만 durable cursor에 저장한다. 중단 시 마지막 provisional 범위는 원음에서 다시 처리하며, 같은 발언 ID와 개정 번호를 사용한다. 기존 회의의 endpoint 전사는 설정을 유지한다. 스트리밍 API가 없는 실행 환경은 명확한 오류로 종료하고 녹음 원본을 보존한다.

## 검증

실제 회의 녹음의 첫 32초를 임시 복사본으로 실시간 속도로 공급한 시험에서 첫 임시 전사가 프로세스 시작 후 약 2.1~2.5초에 도착했다. 이후 임시 개정은 대체로 1초 안팎~2초 간격이었으며 동시 검사 부하에서 32초 음성의 최종 전사는 약 38초에 도착했다. 종료 후 화자 재분석까지 오류 없이 완료했다. 이 값은 해당 짧은 표본의 관측값이며 장시간 지연·정확도 보증은 아니다. 시험 음성은 스피커로 재생하지 않았고 실제 회의 내용을 API에 새로 전송하지 않았다.
