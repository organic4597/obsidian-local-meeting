# 릴리즈 안정성 검증 0.13.0

검증일: 2026-11-04. 환경: Apple M4, RAM 24GiB, macOS 26.6, Obsidian 1.15.0. ASR은 로컬 한국어 Qwen3-ASR-1.7B MLX 8비트, 화자 분석은 Community-1/MPS를 사용했다. 설치 대상은 Apple Silicon macOS 15 이상이다.

## 결과

빌드와 자동 검사 **221개(TypeScript 145, Python 76)**가 통과했다. `npm audit`의 알려진 취약점은 0개였으며, 두 Python 실행 환경의 설치 패키지 의존성 충돌도 0개였다. npm 검사는 macOS의 공개 신뢰 인증서를 사용했고 인증서 검증을 끄지 않았다.

실제 회의 원본은 읽기만 하고 모든 처리를 임시 복사본에서 수행했다. 음성 재생·마이크 녹음·AI API 요청·캘린더 쓰기는 실행하지 않았다. 보고서에는 전사 본문, 음성 특징, 사용자 설정, 토큰이나 개인 절대 경로를 넣지 않았다.

## 검증 중 수정한 문제

1. 녹음의 비교 해시가 없고 원래 위치도 사라졌을 때 메타데이터만 같다는 이유로 이동 연결을 허용하던 경로를 차단했다. 완료 회의는 처음 등록할 때 WAV 해시를 보관한다.
2. 캐시 manifest가 null·잘못된 자료형·잘못된 시도 경로일 때 캐시를 버리고 새 시도로 계산한다.
3. Python 워커는 운영체제 파일 잠금을 사용한다. 죽은 PID 파일 삭제 경쟁으로 중복 워커가 실행되는 가능성을 제거했고 강제 종료 뒤에도 잠금 소유권이 자동 해제된다. 잠금 파일 자체가 남는 것은 정상이다.

## 한계와 보존 조건

- 실제 화자 정답 자료가 없어 CER·DER나 실명 식별 정확도를 측정하지 않았다. 실시간 잠정 화자와 음성 프로필 자동 배정은 계속 조건과 검토가 필요한 기능이다.
- 수 시간 실회의·배터리/절전·디스크 고갈·네트워크 파일 시스템·여러 장치의 동시 교정 병합을 검증한 것은 아니다.
- 이번 검사는 시스템 오디오를 재생하지 않았으며, 여러 프로세스를 사용하는 앱의 장시간 오디오 캡처 호환성은 기존 미검증 범위다.
- AI 요약과 캘린더 연동의 기존 동작 및 자동 실패 복구 검사를 유지했다. 새 유료 API 호출이나 다른 iCloud 기기까지의 서버 동기화를 이번에 시험하지 않았다.
- 기존 사용자 회의는 일괄 재처리·이동·변환하지 않는다. 저장 경로 연결을 입증할 수 없으면 덮어쓰기나 자동 병합을 수행하지 않는다.

## 재현

```sh
npm run check
.venv/bin/python scripts/verify_release.py --settings <설치된-플러그인-data.json> --output <검증-보고서.json> --seconds 120
```

설정 파일은 로컬 실행 경로와 마지막 회의 WAV를 찾는 데만 읽는다. 시험용 세션은 임시 폴더에 만들고 종료 후 제거하며, 녹음을 소리 내어 재생하지 않는다. 실패 로그는 공개 보고서에 포함하지 않는다.
