# 구현 상태와 설치 검증

기준일: 2026-10-28. 현재 릴리스 준비 버전 0.12.0. 실시간 로컬 텍스트 전사 → 종료 후 Community-1/MPS 화자 구분·단어 정렬 → OpenAI 정리 경로를 적용했다. 최신 기능·검증 범위는 문서 마지막의 0.12.0 절을 따른다. 아래 과거 버전의 기록은 당시 검증 범위다.

## 0.5.0 품질 개선과 검증

- 로컬 SQLite 사전, 범위별 우선순위·제외, 모델 context 힌트, 제한된 한 번의 표기 통일, 원문과 교정 제안 보존.
- PCM 큐와 ASR 문맥 구간 분리, 잠정/확정 전사, 안정 ID와 개정 번호, 프레임별 화자 활동 저장, 후보와 불확실성 보존, 최근 근거 재평가.
- 발언 원음의 메모리 내 구간 재생, 사용자 교정·원문 확인·직전 교정 취소, 입력 진단, 평가 양식·CER/전사 귀속 DER 도구.
- 실제 두 합성 화자를 시간 순서대로 19.386초 동안 공급: 최종 3발언의 화자 1→2→1 유지, 잠정 2개를 포함한 5개 개정 이벤트. 모델 추가 없이 기존 8비트 ASR과 Nemotron 사용.
- 3초 휴지가 있는 19.610초 합성 파일: 같은 화자의 두 발언 보존, 원본 WAV 하나 유지.
- 실제 32분 30.4초 회의를 별도 폴더에 오프라인 처리: 426.37초에 정상 완료, 워커 피크 RSS 2,991,210,496바이트. 원본 파일은 바이트 단위로 동일하고 WAV는 하나다.
- 같은 자료에서 전사 처리 구간은 498→304, 1초 미만 구간은 181→43. 겹침 표시는 87→50, 미확정은 1→14. 이는 처리 구조와 보류 정책의 변화이며 정확도 개선율이 아니다.
- 완료된 품질 세션 복구: 모델 재로딩 없이 304개 동일 결과 재생, 약 0.117초. 원본과 기존 메트릭 보존.
- 기존 회의 노트의 해시와 모델·오디오 경로 설정을 보존하며 설치본을 갱신했다. 기존 회의를 자동 재전사하거나 일괄 교정하지 않았다.
- 최종 빌드와 자동 검사 82개 통과: TypeScript 46개와 Python 36개. 노트 반영 실패·메타데이터 저장 실패·이전 세션의 지연 이벤트를 별도 오류 주입으로 확인했다.
- 실시간 파일 재생 중 사전 변경: 첫 두 확정 발언은 기존 사전 버전을 유지하고, 이후 시작한 세 번째 발언에 새 버전을 적용했다. 해당 1회 실행의 첫 잠정 텍스트 관측은 시작 약 4.69초 후였으며 p95 수치로 일반화하지 않는다.
- 설치된 main.js와 최종 dist 번들의 해시 일치, data.json 설정 보존 확인. 배포 ZIP에는 모델·녹음·개인 설정이 포함되지 않는다.

실제 한국어 회의의 정답 CER·DER 향상률, 30분 실시간 공급의 p95 지연 목표, P2 단어 정렬, P3 음성 표본 인식은 검증/구현 완료로 표시하지 않는다. 신규 모달의 실제 Obsidian 화면·조작 검증은 미완료다. 사용자는 Obsidian이 보인다고 확인했지만 CUA는 잠금으로 반환했고 캡처는 검은 화면이었다. 이전에 허용된 AppleScript로도 앱의 웹 접근성 트리를 읽지 못했으며 설치 앱을 통한 파일 전사 시험의 완료를 확인하지 못했다. 앱 UI 검증을 자동 검사나 별도 워커 검사로 대체해 완료로 표시하지 않는다.

## 0.5.0 당시 화자 모델과 비교 후보

현재 자동 화자 구분은 `Nemotron-3-Diarization.q8_0.gguf`를 NeMo-Speech C ABI로 CPU에서 실행한다. Qwen3-ASR-1.7B는 별도의 MLX 전사 모델이다. 두 모델의 결과를 시간 기준으로 연결하며, 현재 한국어 회의에서 이 조합이 최선이라고 단정하지 않는다.

`pyannote/speaker-diarization-community-1`은 오프라인 비교 후보로 남긴다. 공식 모델 카드의 이용 조건 동의와 사전 다운로드가 필요하며 이번 개선에서 설치하거나 교체하지 않았다. 서로 다른 모델 카드의 DER 숫자는 정답 RTTM·데이터 분할·겹침·collar 조건을 맞추지 않고 순위를 매기지 않는다. [Community-1 공식 자료](https://huggingface.co/pyannote/speaker-diarization-community-1), [Nemotron 공식 자료](https://huggingface.co/nvidia/Nemotron-3-Diarization).

사용자가 제시한 [resilient-stt 설계](https://github.com/gitcommitshow/resilient-stt/blob/main/docs/design.md)는 ASR 결합 후 단어 IoU로 화자를 연결하고 구간 중간점·unknown을 보조로 사용하는 방식을 설명한다. [Taiwan ASR Toolkit](https://github.com/thc1006/taiwan-asr-toolkit)은 Qwen3와 ForcedAligner 및 선택적 pyannote 연결을 설명한다. 전자는 영어·힌디어 계열, 후자는 대만 중국어 중심의 프로젝트이므로 한국어 Mac 회의 성능 근거로 사용하지 않는다. 이 플러그인의 단어 시간 정렬과 IoU 연결은 P2 검증 대상이다.

## 0.4.0 이전 검증 기록

## 실제 설치 및 앱 통합 확인

- 설치 위치: `Obsidian Vault/.obsidian/plugins/local-meeting/`
- 기존 커뮤니티 플러그인 목록을 보존하고 Local Meeting을 추가했다. 기존 설정 백업을 로컬 작업 폴더에 보관했다.
- 모델: 동일 TeamUNIVA 한국어 미세조정 원본을 MLX 8비트 및 혼합 4비트로 변환하고 M4 GPU에서 추론 성공.
- 기본 적용 모델: 8비트. 변환된 모델과 녹음은 Vault 외부에 보관한다.
- Obsidian 안에서 8.305초짜리 한국어 합성 WAV를 전사하고 고정된 테스트 노트 본문에 입력됨을 확인했다.
- Obsidian을 종료 후 다시 열어 세션 복구를 실행했다. 전사 블록은 1개로 유지됐고 중복되지 않았다.
- 저장된 화자 ID/이름의 복구를 확인했다. 화자 이름을 ‘테스트 진행자’로 저장한 테스트 상태가 앱 노트에 반영됐다. UI 입력 버튼을 자동 조작한 테스트는 아니다.
- 발언 블록 안에 직접 수정한 문장을 넣고 복구했을 때 덮어쓰지 않는 것을 확인했다.
- 내장 마이크로 오디오를 녹음해 PCM WAV 저장→SQLite 큐→STT→종료까지 워커 경로를 별도로 실행했다. 이후 사용자가 Obsidian에서 마이크 녹음을 시작한 실제 흐름에서도 32.8초/5개 구간이 본문에 입력되고 모든 큐 작업이 끝났음을 확인했다.

## 자동 검사

- TypeScript strict 빌드 + esbuild 플러그인 번들 성공.
- TypeScript 테스트 8개: 전사 재생 중복 방지, 이름 변경, 사용자 수정/삭제 보존, 워커 메시지 검증.
- Python 테스트 6개: 실행 중 작업 복구, WAV/SQL 사이 중단 복구, 오류 재시도, 종료 시 남은 PCM 저장, 짧은 파일 꼬리 병합, 잘못된 오디오 형식 거부.
- npm audit 취약점 0개 (개발 의존성 포함).

## 미완료와 검증 범위

- 단어 단위 시간 정렬, 임시/확정 스트리밍, 경계 중첩 처리, 요약·결정·할 일·ICS, 시스템 오디오 캡처, 완성된 설치 패키지.
- 현재 녹음은 2초 단위로 저장한다. 화자 모델의 문맥과 발언 구간 확인 후 전사하며 긴 발언은 대략 8초 단위로 처리한다. 시간은 발언 구간 기준이며 단어별 정렬 시간은 아니다.
- 파일 가져오기는 마지막 2초 이하 꼬리를 앞 구간과 함께 전사한다. 실시간 녹음 경계의 누락·중복 문제를 일반적으로 해결한 것은 아니다.
- FLEURS 전체 평가, 다중 화자 실제 회의, 장시간 안정성, 음성 감지와 무음 환각 검증은 아직 하지 않았다.
- 메모리 수치는 ASR 단독의 짧은 샘플 실측이다. [모델 실측 조건](BENCHMARKS.ko.md)을 참조한다.
- 상태의 미처리 오디오 범위는 최초~최후 미완료 구간의 범위이며 wall-clock 지연과 다를 수 있다.

## 0.2.0 추가 검증

- 설치된 Obsidian에서 Nemotron 3 GGUF + NeMo-Speech.cpp C ABI + 한국어 Qwen ASR을 연결했다.
- 한국어 합성 음성 두 종류를 A→B→A 순서로 넣어 `speaker_1 → speaker_2 → speaker_1`을 확인했다. 본문에는 `화자 1: 대사`로 표시했다.
- 고정 파일 조각마다 전사하는 대신 화자 발언 구간을 여러 WAV에 걸쳐 모아 전사한다. 단어 정렬이나 한국어 실회의 DER 평가를 완료한 것은 아니다.
- 본문 관리용 HTML 주석·굵게·기본 시간 표기를 제거했다. 기존 테스트 노트도 관리용 표시를 정리했다.
- 앱 안에서 시간 표시 켜기/끄기를 확인했고, 기본 꺼짐 상태로 돌려놓았다.
- 오른쪽 상단 반투명 상태 아이콘과 상세 보기 최소화, 세 개의 기본 단축키 명령을 등록했다. 키보드 입력 자체를 OS 자동화로 누르는 검사는 하지 않았다.
- macOS에서 캘린더 7개와 iCloud 소스를 확인했다. 선택한 iCloud 캘린더의 향후 7일 조회와 쓰기 가능 조건을 확인했다. 테스트 일정을 실제 iCloud에 임의로 저장하지 않았다.
- 캘린더 생성·플러그인 소유 일정 갱신·노트 할 일 추가 UI를 제공한다. 외부 iCloud 기기까지의 동기화 완료를 확인한 것은 아니다.
- 현재 자동 검사: TypeScript 8개, Python 6개 통과. 이전 수동 화자 전용/8초 고정 구간 설명은 0.1.0 기록이다.

## 0.3.0 UI·UX 개선과 검증

- 캘린더 팝업을 월간 보기와 선택한 날짜의 일정 목록으로 변경했다. 폼은 ‘새 일정’이나 플러그인 소유 일정의 ‘수정’을 눌렀을 때만 연다.
- 개별/전체 캘린더 필터, 캘린더 색, 종일 일정, 월 이동·오늘 이동, 상세 정보, 빈 상태·로딩·오류와 다시 시도를 추가했다. 조회는 보이는 42일 범위로 제한하고 결과 1,000건 초과 시 안내한다.
- 회의 상세 보기의 단일 녹음 제어·명시적인 대상 노트·작은 대기 지표, 참여자 이름과 Enter 저장, 접힌 화자 수정 드롭다운, 참여자 추가를 제공한다. 원시 화자 ID와 구간 ID를 기본 화면에서 제거했다.
- 입력 중 패널 전체를 다시 그리지 않으며, 재표시 시 펼침 상태와 스크롤을 보존한다. 경로 설정을 그룹화하고 파일 존재 여부를 안내한다.
- 설치된 Obsidian 1.14.5에서 실제 EventKit 연결 7개 캘린더를 읽고, 전체 캘린더의 해당 월 공휴일 3건을 달력·선택일 목록·상세 팝업에서 확인했다. 선택한 iCloud 캘린더의 일정 없는 날도 확인했다.
- 실제 앱에서 방향키로 다음 날짜, PageDown으로 다음 달 이동 및 포커스 유지, 빈 제목 저장 시 오류 표시, 화자 이름 Enter 저장 후 테스트 노트 본문 반영을 확인했다.
- `⌘⌥C`를 실제 키 입력으로 실행해 캘린더가 열리는 것을 확인했다. 다른 플러그인의 단축키 설정에 따라 충돌할 수 있다.
- TypeScript 19개 + Python 6개 검사 통과. 실제 iCloud에 임의의 테스트 일정을 생성하지 않았고 다른 기기까지 동기화 완료를 검증하지 않았다. UI 변경이 화자 모델의 실제 회의 정확도를 높였다는 의미는 아니다.

- 0.3.0 재설치 후 별도 테스트 노트에서 19.386초 두 화자 합성 WAV를 다시 처리했다. 3개 발언, 화자 1→2→1, 대기 0개·0초로 종료됐다. 화자 선택을 변경해 해당 발언만 바뀌는지 확인하고 원래 화자로 복원했다.
- 할 일 팝업의 대상 노트, 자동 포커스와 빈 입력 오류를 확인하고 기한 없는 테스트 할 일을 해당 테스트 노트에 저장했다. 오버레이의 저장된 위치와 기존 모델 경로도 그대로 유지됐다.

## 0.4.0 동시 필기·문단·전체 녹음

- 열린 노트에는 CM6 변경 트랜잭션을 적용한다. 커서·다중 선택·스크롤을 매핑하고 자동 전사를 사용자 실행 취소 이력에서 제외한다. 한글 조합 중에는 노트 반영만 대기한다. 닫힌 노트는 원자적 파일 처리 경로를 유지한다.
- 실제 Obsidian에서 66.44초 단일 화자 합성 음성을 처리하면서 메모를 입력하고 이어 썼다. 처리용 발언 9개가 화자 이름 1번으로 합쳐졌고, 사용자 메모와 저장된 노트·메타데이터가 일치했다. 실행 취소 두 번으로 필기만 제거되고 전사는 유지됐으며 다시 실행으로 필기를 복원했다.
- 동일 화자의 기본 문단 경계는 감지된 발언 간격 2.5초 이상이다. 설정에서 2/2.5/3초를 선택하고 새 회의부터 적용한다. 화자 전환·사용자 필기·수정한 발언은 보수적으로 분리한다. 처리 청크 경계 자체로 이름을 반복하지 않는다.
- 실제 모델에 3초 무음을 넣은 동일 화자 합성 음성을 넣어 2개 발언과 2,682ms 간격을 확인했다. 단어 정렬 또는 모든 음향 환경에서 정확한 무음 길이를 보장하는 것은 아니다.

## 2026-10-28 · 0.11.0 개발 버전

Nemotron 모델·라이브러리 설정과 이전 전용 실행 코드를 제거했다. 실시간 전사는 Qwen, 종료 후 화자 구분은 Community-1/MPS다. 기존 완료 회의는 전사와 이름을 보존하면서 Community-1으로 다시 분석할 수 있다. 이전 형식 회의에 미완료 큐, 누락 구간 또는 확인되지 않은 음성 조각이 발견되면 자동 재전사를 중단하고 원본을 보존한다. 수동으로 요청한 화자 재분석은 전사 복구와 별도다. 이 Mac에서 확인한 11개 이전·현재 세션에는 미완료 큐가 없었다.

검증: TypeScript 94개와 Python 49개, 총 143개 자동 검사 통과. 합성 한국어 음성을 Qwen STT→Community-1/MPS로 처리해 오류 없이 완료했다. 설치된 Obsidian 1.14.5의 0.11.0 활성화와 Community-1 설정, 이전 Nemotron 설정 제거를 확인했다. 요약 시간 구간을 편집·읽기 화면에서 각각 클릭했을 때 실제 `재생 중` 상태가 나타났고 닫기 버튼으로 중지했다. 이전 회의 원문·요약·WAV 해시를 보존했다.

이 Mac의 프로젝트 모델 사본, 모델 캐시 사본, 프로젝트 전용 NeMo-Speech 런타임은 휴지통으로 이동했다. Community 모델과 녹음은 보존했다. 화자 수는 설정에서 1~32명 또는 미지정을 지원하며, 32명은 플러그인 설정 한도이지 실제 회의의 화자 분리 정확도 보장이 아니다.


## 2026-10-28 · 0.12.0 검증

- TypeScript 101개와 Python 54개 자동 검사가 통과했다.
- 0.12.0-beta.1을 Obsidian 1.14.5에 설치하고 무음 녹음 시작·종료, 16kHz 단일 WAV와 Community-1 후처리를 확인했다. 합성 음성은 스피커 출력 없이 전사 경로에 공급했다.
- 합성 텍스트로 실제 OpenAI 연결, 응답 형식과 상대 날짜를 검사했다. 기존 정리의 검토 화면, iCloud 일정 양식 및 종일 선택을 확인했다.
- 플러그인에서 고유 테스트 일정을 iCloud 계정의 Mac 캘린더에 저장하고 Mac 캘린더 앱에서 확인한 뒤 정확히 그 일정만 삭제했다. 별도 EventKit 조회에서 삭제를 확인했다. iCloud 서버 및 다른 기기의 동기화는 독립적으로 확인하지 않았다.
- 시스템 오디오는 48kHz 기본 마이크와 현재 출력 중인 프로세스 또는 전체 시스템을 사용한다. 장시간 회의와 여러 하위 프로세스를 사용하는 앱의 호환성·실제 다화자 정확도는 미검증이다.
