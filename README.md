# Obsidian Local Meeting

Apple Silicon Mac용 한국어 회의록 플러그인. 녹음·STT·화자 구분은 로컬에서 수행하고, 선택적으로 OpenAI에 회의 텍스트 정리를 요청합니다.

## 현재 작동 흐름

회의 중에는 로컬 Qwen STT를 고스트 텍스트로 보여주며 같은 노트에서 필기할 수 있습니다. 종료 후 Community-1/MPS와 단어 정렬로 화자를 구분해 본문을 확정하고, 선택적으로 OpenAI에 회의 텍스트를 보내 요약·할 일·일정 후보를 만듭니다. 기존 이름과 직접 수정한 내용을 보호합니다.

요약의 시간 범위는 해당 회의의 로컬 녹음 구간 재생으로 연결됩니다. 0.11.0에서 실제 Obsidian의 편집·읽기 화면으로 클릭 재생을 확인했습니다. 자세한 변경사항은 [릴리스 노트](docs/releases/)와 [GitHub Releases](https://github.com/organic4597/obsidian-local-meeting/releases)를 확인하세요.

OpenAI 연결은 브라우저에서 ChatGPT 계정으로 인증하며 비밀 정보는 Obsidian SecretStorage에 저장합니다. 요약 시 회의 텍스트는 OpenAI에 전송되고 오디오는 전송하지 않습니다. 새 회의의 화자 수는 최대 또는 고정으로 설정할 수 있지만 실제 사람별 정확한 분리를 보장하지 않습니다.

## 공통 구현 기능

- 회의 시작부터 끝까지 **`recording.wav` 하나에 연속 녹음**, 전사용 PCM + SQLite 디스크 큐는 별도로 처리
- 한국어 미세조정 Qwen3-ASR-1.7B MLX 8비트 / 혼합 4비트 지원
- 새 회의는 실시간 STT만 실행하고 종료 후 **Community-1/MPS**로 화자를 구분. 이전 회의의 완료된 전사는 보존하고 Community-1으로 재분석 가능
- 종료 후 발언과 화자 근거를 결합하고, 미수정 문장은 로컬 단어 시간으로 분할. 겹친 발언은 ‘동시 발언’, 불확실한 귀속은 ‘화자 미확정’으로 표시
- 실시간에는 **흐린 고스트 대사**, 종료 후에는 **`화자: 대사`**로 기록. 식별자·HTML 주석·자동 굵게 문법을 본문에 넣지 않음
- 현재 회의의 시간 표시 버튼/단축키. 표시를 켜면 `(00:00:05) 화자 2: 대사` 형태
- STT 중 같은 노트에 동시에 타이핑 가능. 커서·선택 영역·스크롤을 보존하고 한글 조합 중에는 반영 대기. 자동 전사는 필기의 실행 취소 이력에서 제외
- 같은 화자가 계속 말하면 한 문단으로 합치며, 기본 2.5초 이상 빈 구간이나 다른 화자·중간 필기가 있으면 분리. 설정에서 2/2.5/3초 선택 가능
- 사용자가 직접 적은 필기와 수정한 문장은 보호. 원본 매핑과 시간은 Vault 외부의 세션 JSON에 보관
- 원하는 위치로 드래그할 수 있는 반투명 회의록 버튼: 녹음 중에는 빨간 상태 표시, 클릭하면 작은 제어 메뉴
- 드래그 위치는 Vault 설정에 저장되며, 창 크기가 바뀌면 화면 안으로 보정. 메뉴의 ‘버튼 위치 초기화’로 기본 위치 복원
- 사이드바는 상세 보기. 최소화해도 녹음과 전사는 계속됨
- macOS EventKit을 통해 **iCloud 캘린더의 월간 보기·날짜별 일정 목록·일정 생성/갱신**. Apple ID나 앱 전용 암호를 플러그인에 저장하지 않음
- 현재 노트에 선택적으로 기한을 붙인 할 일 체크박스 추가
- 녹음 대상 노트와 단일 시작/종료 버튼, 참여자 이름 편집, 접어서 볼 수 있는 발언별 화자 수정

| 기본 단축키 | 동작 |
| --- | --- |
| `⌘⇧M` | 녹음 시작 / 중지 |
| `⌘⌥M` | 상세 보기 / 최소화 |
| `⌘⌥T` | 현재 회의 시간 표시 켜기 / 끄기 |
| `⌘⌥C` | 연결된 캘린더 팝업 열기 |

Obsidian 설정 → 단축키에서 변경할 수 있습니다.

자동 화자 ID는 실제 이름이 아닙니다. 상세 보기에서 이름을 지정하고 오귀속을 고칠 수 있습니다. 모델을 연결하기 전에 만든 기록은 자동으로 다시 전사하지 않습니다.

## 설치와 개발

Apple Silicon macOS 15+, Python 3.11, Node.js 22+, Swift 컴파일러가 필요합니다.

```sh
npm ci
python3 -m venv .venv
.venv/bin/pip install -r worker/requirements.txt
npm run check
```

새 Python 품질 검사는 NumPy가 설치된 위 가상환경에서 실행한다: `.venv/bin/python -m unittest discover -s tests -p 'test_*.py'`. `npm run check`도 `.venv/bin/python`을 사용한다.

정확도 평가는 검토 화면에서 내보낸 정답 양식의 `referenceText`·`referenceSpeakers`를 원음으로 확인해 채운 뒤 실행한다.

```sh
.venv/bin/python scripts/evaluate_quality.py --reference reference.json --hypothesis transcript.json --output score.json
```

`CER`은 표시 텍스트, `recognitionCER`은 인식 원문, `diarization`은 전사 구간의 화자 귀속 점수다. 원시 화자 모델만의 DER와 구별한다. 같은 평가 시간 범위를 사용하며 빈 정답 양식은 오류로 종료한다.

Mac에서 빌드하면 EventKit 보조 실행 파일도 컴파일합니다. `dist/` 내용 전체를 `<Vault>/.obsidian/plugins/local-meeting/`에 복사하고 커뮤니티 플러그인에서 Local Meeting을 활성화합니다.

ASR Python에는 `worker/requirements.txt`, 별도 Community Python에는 `worker/requirements-community.txt`를 설치합니다. Community-1 모델 이용 조건에 동의하고 모델을 미리 내려받아야 합니다. 설정에 ASR Python·모델, Vault 외부 녹음 저장 폴더, Community 전용 Python·로컬 모델, 대사 정렬 모델 경로를 지정합니다. 회의 중에는 모델을 자동 다운로드하지 않습니다.

### ASR 모델 준비

`TeamUNIVA/qwen3_asr_1.7b_ko` 원본 체크포인트를 미리 내려받은 뒤 변환합니다. 변환은 로컬 파일만 읽습니다.

```sh
.venv/bin/python scripts/prepare_model.py --source /path/to/original --output /path/to/korean-q8 --bits 8
.venv/bin/python scripts/prepare_model.py --source /path/to/original --output /path/to/korean-mixed4 --bits 4
```

혼합 4비트는 인코더 8비트·디코더 4비트입니다. [현재 M4 실측](docs/BENCHMARKS.ko.md)을 참조하세요.

## 사용

Markdown 노트를 연 뒤 `⌘⇧M`으로 시작합니다. 녹음 대상 노트는 시작 시 고정됩니다. 녹음 중 다른 노트로 이동해도 대상이 바뀌지 않습니다. 시작 후에도 본문에 자유롭게 필기할 수 있습니다. 메모를 입력하는 동안 전사 워커는 독립적으로 처리합니다.

한글을 조합하는 동안에도 녹음과 STT는 계속되고, 글자가 확정되면 대기하던 결과를 노트에 반영합니다. 설정의 문단 나누기 기준은 새 회의부터 적용하며 모델이 감지한 발언 간격을 사용합니다. 사용자가 수정한 발언이나 사이에 삽입한 필기를 가로질러 문단을 합치지 않습니다.

`⌘⌥M`으로 상세 보기를 열어 화자 이름과 개별 발언 귀속을 수정합니다. 수동 지정은 자동 결과보다 우선합니다. 중지하면 새 녹음을 끝낸 뒤 남은 구간을 처리합니다. 중간 종료 시 ‘마지막 세션 복구’ 명령으로 원본 오디오를 다시 처리할 수 있습니다. 이전 형식의 완료된 회의는 Community-1으로 재분석합니다. 이전 형식에 미완료 큐가 있으면 자동 변환을 중단하고 원본을 보존합니다.

회의 전체 PCM WAV를 녹음 시작 때 생성하고, 수신되는 오디오를 같은 파일에 계속 추가합니다. 헤더도 갱신하므로 녹음 중 파일을 읽을 수 있습니다. 전사용 내부 큐는 기본 2초 단위 PCM 조각으로 저장합니다. 화자 모델의 앞뒤 문맥과 말끝 확인, STT 시간이 추가되므로 전체 표시 지연이 2초라는 뜻은 아닙니다. 새 회의의 STT는 약 0.9초의 쉼 또는 최대 20초에서 확정하고 발화 중 잠정 반복 전사를 하지 않습니다. 이전 세션의 복구는 기존 경로를 유지합니다. 현재는 시스템 소리를 직접 캡처하지 않습니다.

## 회의 전체 녹음 파일

회의별 저장 폴더의 **`recording.wav` 하나**가 시작부터 종료까지의 녹음입니다. 형식은 16kHz·모노·16비트 PCM이며, STT 처리 지연과 관계없이 별도 디스크 작성 스레드에서 저장합니다. 회의 전체를 RAM에 모아 두지 않습니다.

상세 보기의 **녹음 파일 보기** 또는 같은 이름의 명령으로 Finder에서 전체 WAV를 바로 찾을 수 있습니다. 저장 구조는 `<오디오 저장 폴더>/<회의 ID>/recording.wav`입니다. `queue/`의 PCM 조각과 SQLite는 전사·복구용 내부 데이터이며 재생용 WAV는 아닙니다. 전체 녹음과 내부 큐는 Vault 외부에 보관합니다.

이전 버전의 WAV 조각은 녹음 파일을 처음 열거나 세션을 복구할 때 전체 WAV로 모을 수 있습니다. 기존 원본 조각은 보존합니다. 중단 시 전체 WAV 헤더와 미처리 꼬리를 복구하며, 녹음 원본을 자동 삭제하지 않습니다.

## iCloud 일정과 할 일

아이콘 메뉴 또는 상세 보기 → **캘린더 열기** 또는 `⌘⌥C`를 사용합니다. 처음에는 macOS 캘린더 권한이 필요합니다. 이 Mac에 iCloud 캘린더가 등록돼 있어야 합니다.

팝업을 열면 현재 월의 실제 일정을 자동으로 불러옵니다. 캘린더 하나 또는 ‘모든 캘린더’를 선택하고, 날짜를 누르면 그날의 일정과 시간·캘린더·장소를 볼 수 있습니다. 캘린더 색으로 출처를 표시하고, 일정 카드를 누르면 상세 내용이 열립니다. 종일·여러 날짜 일정과 월 경계를 지원합니다. 날짜에서 방향키, Home/End, PageUp/PageDown을 사용할 수 있습니다.

‘새 일정’을 누르면 선택한 날짜의 입력 폼이 열립니다. 제목·시작·종료·장소·메모를 확인하고 ‘캘린더에 저장’을 누르면 macOS가 저장과 iCloud 동기화를 담당합니다. 플러그인이 만든 일정은 상세 팝업에서 수정할 수 있고, 다른 일정은 읽기 전용으로 표시합니다. 같은 편집 창은 같은 고유 ID를 사용하며 저장 중 중복 제출을 막습니다. 외부 캘린더 API나 비밀번호는 필요하지 않습니다.

상세 보기나 오버레이의 ‘할 일 추가’는 폼을 열었을 때 선택된 노트에 체크박스를 추가합니다. 기한은 선택 사항입니다. 일정 내용을 자동 추측해 캘린더에 등록하지 않습니다.

## 브랜치와 릴리스

`main`은 배포 기준, `develop`은 개발 통합, `release/<버전>`은 릴리스 준비에 사용합니다. 자세한 흐름은 [브랜치 운영](docs/BRANCHING.ko.md), 버전별 변경은 [릴리스 노트](docs/releases/)를 참고하세요.
