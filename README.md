# Obsidian Local Meeting

Apple Silicon Mac용 한국어 회의록 플러그인. 녹음·STT·화자 구분은 로컬에서 수행하고, 선택적으로 OpenAI에 회의 텍스트 정리를 요청합니다.

## 0.8.0 · 고스트 전사와 자연스러운 글자 표시

새 회의의 실시간 전사는 노트 하단의 흐린 고스트 텍스트로 나타난다. 편집기 장식으로 표시하며 Markdown 본문·커서·실행 취소 이력을 변경하지 않는다. 전사와 교정은 회의별 로컬 데이터에 계속 저장하고, 회의를 복구하거나 노트를 다시 열면 미리보기를 복원한다. 고스트 대사를 수정하려면 발언 검토를 사용하고 본문에는 필기를 자유롭게 입력한다. 읽기 모드에서는 장식을 표시하지 않으므로 편집 모드에서 확인한다.

종료 후 Community-1/MPS와 단어 정렬이 끝나면 화자별 확정 대화를 일반 글자 색으로 이어서 보여주고 본문에 저장한다. 글자 표시만 애니메이션으로 처리하므로 매 글자마다 파일을 쓰거나 STT를 다시 호출하지 않는다. 긴 실시간 업데이트는 최대 약 1.2초, 확정 기록은 최대 약 8초로 표시 시간을 제한하며, 시스템의 동작 줄이기를 사용하거나 노트가 닫혀 있으면 즉시 저장한다. 실제 ASR 결과는 발언 종료 또는 최대 문맥 길이 이후 도착하며, 이 효과가 음성 인식 자체를 글자 단위 스트리밍으로 바꾸지는 않는다.

확정 전 계획을 먼저 저장해 중단 후 이미 기록된 본문을 중복 삽입하지 않는다. 복구 시 본문이 계획과 다르면 임시 전사를 보존하고 확인을 안내한다. 후처리 오류 시에도 명령 팔레트 또는 오버레이의 **임시 전사를 본문으로 확정**으로 전사만 저장할 수 있다. 기존 회의와 직접 수정한 본문은 이 표시 방식으로 변환하지 않는다. AI 요약·할 일·일정은 기존처럼 별도 정리 노트를 사용한다.

## 0.7.0 · 텍스트 전사 → Community-1/MPS → OpenAI 정리

새 회의의 실시간 경로는 STT만 실행한다. `pending` 화자 표시는 노트에 쓰지 않는다. 2초 원음 큐와 단일 WAV 저장은 유지하며, 쉼 또는 최대 20초에서 대사를 확정한다. 이전 회의 복구는 원래 파이프라인을 유지한다.

회의 시작 창에서 0~32명의 화자 수와 적용 방식을 선택한다. **상한**은 Community-1의 `max_speakers`, **고정 인원**은 `num_speakers`로 전달한다. 상한 7명은 자동 검출이 6명이면 6명으로 남길 수 있으며, 고정 7명도 실제 사람별 정확한 분리의 보장은 아니다. 설정의 인원은 새 회의 시작 창의 기본값이고, 실제 선택값은 회의별 `pipeline.json`과 `meeting.json`에 보존한다.

회의 종료 후 ASR 자원을 해제하고 별도 Python 프로세스에서 로컬 Community-1/MPS를 실행한다. MPS를 사용할 수 없으면 CPU로 몰래 전환하지 않고 오류와 재시도 경로를 제공한다. 여러 화자가 걸친 미수정 발언은 로컬 Qwen3 ForcedAligner의 단어 시간으로 나누며, 원래 문자열과 문자 위치를 대조한다. 수정·삭제된 본문은 자동 분할하지 않는다. 원음과 원래 전사, 적용 전 스냅샷을 보존한다.

OpenAI 연결은 공식 **Sign in with ChatGPT** 공개 클라이언트 흐름이다. 시스템 브라우저, PKCE, state·nonce 검증, JWKS 서명/issuer/audience/만료 검증, 계정별 client ID, 갱신 토큰 회전, 로그아웃을 구현했다. 비밀 정보는 Obsidian SecretStorage에 저장하며 플러그인 data.json·회의 노트·로그에 넣지 않는다. 기존 Codex 인증 파일은 읽지 않는다. ChatGPT 사용 권한이 승인된 계정의 모델 목록을 표시하며 실제 모델 사용 권한은 완료된 요청으로 검증한다. 계정·요금제·지역·사용량 제한은 OpenAI가 판단한다. API 키가 필요한 별도의 결제 경로는 이 버전에 구현하지 않았다.

화자 구분 완료 후 최신 문서와 사용자 필기, 발언 ID를 OpenAI Responses API로 보내 요약·결정·할 일·일정 후보·확인 사항을 정리한다. 오디오는 보내지 않는다. OAuth 요청 계약에 따라 `store:false`, `stream:true`를 사용한다. 완료 이벤트와 출력 형식·근거 ID를 검증한 결과만 저장한다. 정리 노트는 원문 옆의 별도 파일이며, 기존 정리 노트를 덮어쓰지 않는다. 처리 중 원문 변경이 있으면 이전 스냅샷 기준임을 표시한다. 일정 후보는 편집 가능한 캘린더 저장 화면을 거쳐 등록한다.

설치 환경: 기존 MLX Python에 `worker/requirements.txt`, 분리한 Community Python에 `worker/requirements-community.txt`를 설치한다. Community-1 공식 이용 조건에 동의하고 모델을 로컬에 내려받은 후 설정에서 경로를 지정한다. 정렬 모델은 `mlx-community/Qwen3-ForcedAligner-0.6B-4bit` 로컬 폴더를 사용한다. 설치자가 플러그인 폴더의 `local-runtime.json`에 `communityPython`, `communityModel`, `alignerModel` 절대 경로를 기록하면 비어 있는 설정의 초기값으로 읽는다. 이 파일에는 토큰을 저장하지 않는다.

## 0.5.0 변경 이력 · 사전과 화자 처리 개선

- 개인·Vault·프로젝트·회의 사전: 표준 용어·발음·확인된 오인식, 범위별 우선순위와 비활성화, JSON 가져오기·JSON/CSV 내보내기
- 인식 전 로컬 ASR 문맥 힌트(최대 40항목·256토큰), 허용된 별칭 표기 통일과 교정 제안. 원문은 별도 보존
- 새 회의는 PCM 작업과 독립적으로 문맥을 유지하는 발언을 처리하고 최근 잠정 전사를 같은 ID의 개정으로 갱신
- 화자 활동 확률과 후보 ID를 보존하고 최근 10초의 화자 근거를 재평가. 불확실한 귀속을 강제하지 않음
- 발언 검토에서 원음 구간 재생·대사/화자 교정·직전 교정 취소·확인 완료. 직접 수정·삭제한 본문은 보호
- 실제 입력 장치·레벨·클리핑·입력 오류 진단, 개인정보·전사 본문을 제외한 진단 내보내기
- 정답 입력 양식과 로컬 CER·전사 화자 귀속 DER 평가 도구. 정답이 없는 자료는 점수를 계산하지 않음

첫 개선판은 [품질 설계서](docs/LOCAL-QUALITY-DESIGN.ko.md)의 P0~P1 범위다. 기존 회의는 자동 재전사하지 않으며 이전 큐 복구 경로를 유지한다. 0.5.0 당시 단어 정렬과 음성 표본 대조는 미구현이었다. 0.7.0은 미수정 대사의 로컬 단어 정렬을 추가했으며, 사용자 음성 표본 등록은 아직 지원하지 않는다.

사이드바의 **회의 사전**과 **발언 검토**, 오버레이 메뉴 또는 명령 팔레트에서 연다. 사전 변경은 현재 추론이 끝난 이후 발언부터 적용하며 과거 노트를 자동으로 바꾸지 않는다. 화자 활동의 퍼센트는 실제 사람의 신원 정확도가 아니다.

## 공통 구현 기능

- 회의 시작부터 끝까지 **`recording.wav` 하나에 연속 녹음**, 전사용 PCM + SQLite 디스크 큐는 별도로 처리
- 한국어 미세조정 Qwen3-ASR-1.7B MLX 8비트 / 혼합 4비트 지원
- 새 회의는 실시간 STT만 실행하고 종료 후 **Community-1/MPS**로 화자를 구분. 이전 Nemotron 세션의 복구 경로 유지
- 종료 후 발언과 화자 근거를 결합하고, 미수정 문장은 로컬 단어 시간으로 분할. 겹친 발언은 ‘동시 발언’, 불확실한 귀속은 ‘화자 미확정’으로 표시
- 실시간에는 **흐린 고스트 대사**, 종료 후에는 **`화자: 대사`**로 기록. 식별자·HTML 주석·자동 굵게 문법을 본문에 넣지 않음
- 현재 회의의 시간 표시 버튼/단축키. 표시를 켜면 `(00:00:05) 화자 2: 대사` 형태
- STT 중 같은 노트에 동시에 타이핑 가능. 커서·선택 영역·스크롤을 보존하고 한글 조합 중에는 반영 대기. 자동 전사는 필기의 실행 취소 이력에서 제외
- 같은 화자가 계속 말하면 한 문단으로 합치며, 기본 2.5초 이상 빈 구간이나 다른 화자·중간 필기가 있으면 분리. 설정에서 2/2.5/3초 선택 가능
- 사용자가 직접 적은 필기와 수정한 문장은 보호. 원본 매핑과 시간은 Vault 외부의 세션 JSON에 보관
- 원하는 위치로 드래그할 수 있는 반투명 회의록 버튼: 녹음 중에는 빨간 상태 표시, 클릭하면 작은 제어 메뉴
- 드래그 위치는 Vault 설정에 저장되며, 창 크기가 바뀌면 화면 안으로 보정. 메뉴의 ‘버튼 위치 초기화’로 기본 위치 복원
- 사이드바는 상세 보기. 최소화해도 녹음과 전사는 계속됨
- macOS EventKit을 통해 **iCloud 캘린더의 월간 보기·날짜별 일정 목록·일정 생성/갱신**. Apple ID나 앱 전용 암호를 플러그인에 저장하지 않음
- 현재 노트에 선택적으로 기한을 붙인 할 일 체크박스 추가
- 녹음 대상 노트와 단일 시작/종료 버튼, 참여자 이름 편집, 접어서 볼 수 있는 발언별 화자 수정

| 기본 단축키 | 동작 |
| --- | --- |
| `⌘⇧M` | 녹음 시작 / 중지 |
| `⌘⌥M` | 상세 보기 / 최소화 |
| `⌘⌥T` | 현재 회의 시간 표시 켜기 / 끄기 |
| `⌘⌥C` | 연결된 캘린더 팝업 열기 |

Obsidian 설정 → 단축키에서 변경할 수 있습니다.

자동 화자 ID는 실제 이름이 아닙니다. 상세 보기에서 이름을 지정하고 오귀속을 고칠 수 있습니다. 모델을 연결하기 전에 만든 기록은 자동으로 다시 전사하지 않습니다.

## 설치와 개발

Apple Silicon macOS 15+, Python 3.11, Node.js 22+, Swift 컴파일러가 필요합니다.

```sh
npm ci
python3 -m venv .venv
.venv/bin/pip install -r worker/requirements.txt
npm run check
```

새 Python 품질 검사는 NumPy가 설치된 위 가상환경에서 실행한다: `.venv/bin/python -m unittest discover -s tests -p 'test_*.py'`. `npm run check`도 `.venv/bin/python`을 사용한다.

정확도 평가는 검토 화면에서 내보낸 정답 양식의 `referenceText`·`referenceSpeakers`를 원음으로 확인해 채운 뒤 실행한다.

```sh
.venv/bin/python scripts/evaluate_quality.py --reference reference.json --hypothesis transcript.json --output score.json
```

`CER`은 표시 텍스트, `recognitionCER`은 인식 원문, `diarization`은 전사 구간의 화자 귀속 점수다. 원시 화자 모델만의 DER와 구별한다. 같은 평가 시간 범위를 사용하며 빈 정답 양식은 오류로 종료한다.

Mac에서 빌드하면 EventKit 보조 실행 파일도 컴파일합니다. `dist/` 내용 전체를 `<Vault>/.obsidian/plugins/local-meeting/`에 복사하고 커뮤니티 플러그인에서 Local Meeting을 활성화합니다.

설정에 ASR Python·모델, Vault 외부 녹음 저장 폴더, Community 전용 Python·로컬 모델, 대사 정렬 모델 경로를 지정합니다. 이전 회의 복구용 Nemotron 경로는 별도로 유지합니다. 회의 중에는 모델을 자동 다운로드하지 않습니다.

### ASR 모델 준비

`TeamUNIVA/qwen3_asr_1.7b_ko` 원본 체크포인트를 미리 내려받은 뒤 변환합니다. 변환은 로컬 파일만 읽습니다.

```sh
.venv/bin/python scripts/prepare_model.py --source /path/to/original --output /path/to/korean-q8 --bits 8
.venv/bin/python scripts/prepare_model.py --source /path/to/original --output /path/to/korean-mixed4 --bits 4
```

혼합 4비트는 인코더 8비트·디코더 4비트입니다. [현재 M4 실측](docs/BENCHMARKS.ko.md)을 참조하세요.

### 이전 버전용 Nemotron 모델 준비

```sh
sh scripts/install_diarization.sh
```

NVIDIA 공식 NeMo-Speech.cpp 0.2.0 Mac Metal 배포판을 내려받아 체크섬을 확인하고, 버전과 해시가 고정된 Nemotron 3 모델을 준비합니다. 회의 중에는 로컬 C ABI로 실행하며 HTTP 서버를 사용하지 않습니다. 화자 모델은 CPU, ASR은 Metal GPU를 사용합니다.

## 사용

Markdown 노트를 연 뒤 `⌘⇧M`으로 시작합니다. 녹음 대상 노트는 시작 시 고정됩니다. 녹음 중 다른 노트로 이동해도 대상이 바뀌지 않습니다. 시작 후에도 본문에 자유롭게 필기할 수 있습니다. 메모를 입력하는 동안 전사 워커는 독립적으로 처리합니다.

한글을 조합하는 동안에도 녹음과 STT는 계속되고, 글자가 확정되면 대기하던 결과를 노트에 반영합니다. 설정의 문단 나누기 기준은 새 회의부터 적용하며 모델이 감지한 발언 간격을 사용합니다. 사용자가 수정한 발언이나 사이에 삽입한 필기를 가로질러 문단을 합치지 않습니다.

`⌘⌥M`으로 상세 보기를 열어 화자 이름과 개별 발언 귀속을 수정합니다. 수동 지정은 자동 결과보다 우선합니다. 중지하면 새 녹음을 끝낸 뒤 남은 구간을 처리합니다. 중간 종료 시 ‘마지막 세션 복구’ 명령으로 원본 오디오를 다시 처리할 수 있습니다.

회의 전체 PCM WAV를 녹음 시작 때 생성하고, 수신되는 오디오를 같은 파일에 계속 추가합니다. 헤더도 갱신하므로 녹음 중 파일을 읽을 수 있습니다. 전사용 내부 큐는 기본 2초 단위 PCM 조각으로 저장합니다. 화자 모델의 앞뒤 문맥과 말끝 확인, STT 시간이 추가되므로 전체 표시 지연이 2초라는 뜻은 아닙니다. 새 회의의 STT는 약 0.9초의 쉼 또는 최대 20초에서 확정하고 발화 중 잠정 반복 전사를 하지 않습니다. 이전 세션의 복구는 기존 경로를 유지합니다. 현재는 시스템 소리를 직접 캡처하지 않습니다.

## 회의 전체 녹음 파일

회의별 저장 폴더의 **`recording.wav` 하나**가 시작부터 종료까지의 녹음입니다. 형식은 16kHz·모노·16비트 PCM이며, STT 처리 지연과 관계없이 별도 디스크 작성 스레드에서 저장합니다. 회의 전체를 RAM에 모아 두지 않습니다.

상세 보기의 **녹음 파일 보기** 또는 같은 이름의 명령으로 Finder에서 전체 WAV를 바로 찾을 수 있습니다. 저장 구조는 `<오디오 저장 폴더>/<회의 ID>/recording.wav`입니다. `queue/`의 PCM 조각과 SQLite는 전사·복구용 내부 데이터이며 재생용 WAV는 아닙니다. 전체 녹음과 내부 큐는 Vault 외부에 보관합니다.

이전 버전의 WAV 조각은 녹음 파일을 처음 열거나 세션을 복구할 때 전체 WAV로 모을 수 있습니다. 기존 원본 조각은 보존합니다. 중단 시 전체 WAV 헤더와 미처리 꼬리를 복구하며, 녹음 원본을 자동 삭제하지 않습니다.

## iCloud 일정과 할 일

아이콘 메뉴 또는 상세 보기 → **캘린더 열기** 또는 `⌘⌥C`를 사용합니다. 처음에는 macOS 캘린더 권한이 필요합니다. 이 Mac에 iCloud 캘린더가 등록돼 있어야 합니다.

팝업을 열면 현재 월의 실제 일정을 자동으로 불러옵니다. 캘린더 하나 또는 ‘모든 캘린더’를 선택하고, 날짜를 누르면 그날의 일정과 시간·캘린더·장소를 볼 수 있습니다. 캘린더 색으로 출처를 표시하고, 일정 카드를 누르면 상세 내용이 열립니다. 종일·여러 날짜 일정과 월 경계를 지원합니다. 날짜에서 방향키, Home/End, PageUp/PageDown을 사용할 수 있습니다.

‘새 일정’을 누르면 선택한 날짜의 입력 폼이 열립니다. 제목·시작·종료·장소·메모를 확인하고 ‘캘린더에 저장’을 누르면 macOS가 저장과 iCloud 동기화를 담당합니다. 플러그인이 만든 일정은 상세 팝업에서 수정할 수 있고, 다른 일정은 읽기 전용으로 표시합니다. 같은 편집 창은 같은 고유 ID를 사용하며 저장 중 중복 제출을 막습니다. 외부 캘린더 API나 비밀번호는 필요하지 않습니다.

상세 보기나 오버레이의 ‘할 일 추가’는 폼을 열었을 때 선택된 노트에 체크박스를 추가합니다. 기한은 선택 사항입니다. 일정 내용을 자동 추측해 캘린더에 등록하지 않습니다.

### 0.6.0 · 발화 종료와 회의 종료 후 화자 보정

- 실시간은 기존 `v3-streaming`, 녹음 종료와 남은 전사 완료 후에는 같은 Q8 모델의 `v3-offline` 설정으로 전체 WAV를 다시 처리합니다. 이는 큰 문맥 버퍼를 쓰는 스트리밍 상태 머신 프리셋이며, 별도의 무제한 full-attention 추론이 아닙니다.
- 원음 저장 큐는 2초 간격을 유지합니다. STT는 발화 종료(약 0.9초 쉼)에서 한 번 요청하고, 긴 연속 발언은 최대 20초에서 분할합니다. 발화 중 3초마다 같은 내용을 반복 전사하던 동작은 제거했습니다. 음량 기반 무음 힌트(-50dBFS)는 경계 선정에만 쓰며 원음을 삭제하지 않습니다. 소음이 큰 곳의 종료점 정확도에는 한계가 있습니다.
- 같은 문단의 이어지는 대사에는 시간을 반복하지 않습니다. 시간 표시를 켜면 문단 시작에만 나옵니다. 문단 구분 간격(기본 2.5초)은 인식 요청의 쉼 기준(0.9초)과 별도입니다.
- 화자 재분석은 대사·타임스탬프·구간 ID를 다시 만들지 않습니다. 사용자 지정 화자, 본문에서 수정·삭제한 구간, 필기는 보존합니다. 기존 이름은 시간 겹침으로 일대일 대응하고 새로 분리된 군집에 같은 이름을 중복 상속하지 않습니다. 한 문장에 여러 화자가 섞이면 단어 시간을 추측해 분할하지 않고 검토 대상으로 남깁니다.
- 결과는 `speaker-refinement.json`, 적용 전 상태는 `meeting.pre-speaker-<pass>.json`에 남습니다. 재시작 후 같은 결과는 중복 적용하지 않습니다. 재분석 실패 시 실시간 결과를 유지하고 세션 복구로 재시도합니다. 명령 팔레트의 **현재 회의 종료 후 화자 재분석**은 기존 회의에도 사용할 수 있습니다.
- 설정의 **예상 발언 인원**은 부족 검출 경고 기준입니다. 지정하지 않으면 등록된 이름 수를 참고합니다. Nemotron의 최대 8개 슬롯은 7명 모두를 정확하게 분리한다는 보장이 아닙니다. 현재 C ABI에는 인원 강제 지정·사용자 음성 등록 기능이 없습니다. 7명이 6개 군집으로 합쳐졌을 때 자동으로 가짜 7번째 화자를 만들지 않습니다. 수동으로 새 참여자를 지정하고 원음을 검토해야 하며, 신뢰할 수 있는 자동 분리를 위해서는 추후 음성 표본 기반 임베딩/클러스터링 단계가 필요합니다.
